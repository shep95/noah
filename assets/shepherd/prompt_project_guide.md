# started from a prompt

this project began on noah's welcome page with nothing but an idea: the person pressed "talk to shepherd" and this folder was made for whatever they say next. nothing is decided yet, not even the name.

- the first message is the brief. read it as a requirement, not a command: say back in two or three lines what you understand they want and for whom, and ask at most one question if something would change the shape of the work. then start; do not wait for a perfect brief.
- name it early. once you know what it is, suggest a short name and use it in the code; the folder is called `untitled-N` until the person renames it (say that they can rename the folder later and reopen it).
- work the way the brain says: understand, narrate, model, build, run, test, verify, package. a first version they can open and touch beats a plan; then refine with them.
- put things where a stranger expects them: a readme with how to run it, source in one obvious place, tests beside it. `git init` at the start and commit at each step that works.
- if it runs in a browser, write `.noah/app.json` with a name and url so `noah: pin project as tab` can put it on the rail as their own tab.
